Thank you for contributing to Civic Issue Finder! We appreciate clear, consistent contributions — especially small pull requests that are easy to review.

## Branch naming

- Include the issue ID in your branch name so changes are easy to trace. Use the pattern:

  `<type>/issue-<number>-short-description`

  Examples:

  - `feature/issue-18-readme-updates`
  - `fix/issue-42-rate-limit-bug`
  - `chore/issue-101-deps`

  Common types: `feature`, `fix`, `chore`, `docs`, `refactor`, `test`.

## Pull Request (PR) title and description

- Start PR titles with the issue ID where possible, and a short, descriptive summary. Example:

  `Issue #18 — Update README with contribution guidelines`

- In the PR description, include:
  - A short summary of the change.
  - A link to the related issue (e.g., `Closes #18` or `Fixes #18`).
  - Any setup or testing steps reviewers should follow.

## Commit messages

- Keep commit messages clear and concise. Where applicable, reference the issue number in the commit message. Examples:

  - `Fix: include issue id in branch name (#18)`
  - `Docs: add contributing guidelines (issue-18)`

- For larger changes, consider splitting into multiple small, focused commits.

## Help & etiquette

- If you're unsure where to start, open an issue first describing the problem or feature — maintainers will help scope it.
- Be responsive to review feedback and update your branch as requested.
- Thanks for helping improve Civic Issue Finder!
